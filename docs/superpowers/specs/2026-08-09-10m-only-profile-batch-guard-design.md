# 10分钟单周期与完整画像批次守卫设计

## 实施阶段说明

2026-08-09 用户将实施拆分为独立阶段。第一阶段只删除不参与生产的30分钟订单周期分支，并以10分钟特征测试保证当前画像身份和开单语义不变。仍参与10分钟判断的 `mtf_30m_bias`、完整画像批次守卫以及本设计其余策略调整全部延后，不进入第一阶段提交。

## 目标

在不改变当前线上主要开单来源、不重新收紧评分阈值、不执行历史回测的前提下，完成两项调整：

1. 删除所有仍参与运行的30分钟策略逻辑，只保留“已闭合1分钟K线作为行情源、10分钟事件合约作为交易目标”。
2. 将当前按单笔连续亏损计数的局部守卫改为按完整画像键和真实订单批次判断，避免两笔重叠订单被误判成两个独立失败信号。

本设计先保证当前订单量和已观察到的胜率基线，再为后续按真实订单逐步优化提供准确状态。实施阶段只修改代码、测试、当前策略文档和页面状态，不回放、不清空生产订单、不部署服务器。

## 非目标

- 不加入4小时、日线或其他趋势周期。
- 不使用30分钟信号参与10分钟开单方向、评分、风险或画像。
- 不调整每日画像的60%胜率、EV、样本量、7天观察窗口及每日切换时刻。
- 不调整当前 `TRADE_SCORE_THRESHOLD=0` 的生产放开方式。
- 不调整总未结订单2笔、最小开单间隔2分钟或 `10U -> 18U` 两阶段金额。
- 不根据本次改动重新拟合 edge 或其他指标参数。
- 不删除历史审计文档和数据库中已经保存的30分钟字段；历史数据只读兼容。

## 当前基线

当前实际订单的主要路径不是高分指标信号，而是每日画像对实时观察候选的精确授权：

1. 已闭合1分钟K线生成10分钟技术特征和当前K线形态。
2. 10分钟主策略先判断；主策略没有明确方向时，使用单根已闭合1分钟K线的影线与收盘位置生成观察候选：
   - 收盘强度不高于0.35，且上影线大于下影线1.2倍，生成 `generic_short_observe`。
   - 收盘强度不低于0.65，且下影线大于上影线1.2倍，生成 `generic_long_observe`。
3. 每日画像按完整键精确匹配并决定该候选是否可开单。
4. 评分阈值当前为审计值，不绕过画像、并发、间隔、滚动守卫和结算守卫。

每日画像完整键固定为：

```text
timeframe_minutes | strategy_family | strategy_tag | direction | threshold_segment
```

本次必须保留现有 `generic_short_observe`、`generic_long_observe` 标签和策略族，避免历史画像键失配导致订单量再次归零。

## 决策一：运行态只保留10分钟

### 数据边界

- 输入仍为币安已闭合1分钟K线。
- 技术指标、量能、K线形态和短波段特征都从同一份1分钟序列计算。
- 输出只分析和交易10分钟事件合约。
- 画像、edge、动态阈值、订单、守卫和页面状态的 `timeframe_minutes` 只接受10。

“只保留10分钟”不等于删除按天统计：30天回看窗口、60天滚动守卫窗口和 Fear & Greed 30日均值是统计跨度，不是30分钟行情周期，继续保留。

### 删除范围

运行代码中删除：

- 30分钟K线聚合和 `mtf_30m_bias` 计算；
- `Signal`、快照、API、页面和订单画像中的 `mtf_30m_bias` 当前字段；
- 30分钟分时段 edge 表、门槛修正、最小 edge、候选排序惩罚及对应配置；
- SHORT 指标评分中的30分钟偏向加分；
- 同时依赖10分钟和30分钟方向的风险标签；
- 当前测试、启动说明和当前策略文档中的30分钟运行分支。

历史发布文档可以保留当时的30分钟描述，但必须明确它们是历史记录，不是当前可执行逻辑。

### 10分钟替代规则

删除30分钟输入后，不引入新的周期补位。原有必须继续表达的风险只使用10分钟信息：

- 低波动区间判断由 `abs(mtf_30m_bias) < 1` 改为 `abs(mtf_10m_bias) < 1`。
- 严格反弹风险由“RSI较高，或10/30分钟同时向上且极度恐慌”改为“RSI较高，或10分钟向上且极度恐慌”。
- 宽松反弹风险由“10/30分钟同时向上，或BOLL位置较高”改为“10分钟向上，或BOLL位置较高”。
- `DUAL_UP_BIAS_REBOUND` 重命名为 `TEN_MINUTE_UP_BIAS_REBOUND`，只表达10分钟向上偏向。
- SHORT 指标评分直接移除30分钟加分，不把这部分分值转移给其他指标。

这些替代只用于消除失效依赖，不调整现有阈值数值。

## 决策二：明确 LONG 与 SHORT 候选边界

将当前通用观察方向拆成两个可独立测试的纯判断函数，但保持行为和标签不变：

- `generic_short_observe` 只负责上影拒绝形态。
- `generic_long_observe` 只负责下影收复形态。
- 10分钟主策略已经产生明确 LONG 或 SHORT 时，主策略优先。
- 只有主策略为 WAIT 或没有方向时，才允许通用形态提供观察候选。
- 任一模块都不得把 LONG 自动反转为 SHORT，或把 SHORT 自动反转为 LONG。
- 每日画像只能授权同方向、同策略、同时段候选，不能替候选决定方向。

这一步是结构拆分，不改变0.35、0.65和1.2倍影线比例，也不改变当前订单量预期。

## 决策三：完整画像批次守卫

### 守卫键

批次守卫使用订单最终保存的完整 `profile_key`：

```text
10 | strategy_family | strategy_tag | LONG/SHORT | WD/WE-hour
```

若旧订单没有保存 `profile_key`，只允许使用订单已有字段按同一格式重建。不能退化成仅方向、仅时段或仅策略标签。

因此某个 `WD-08 generic_short_observe SHORT` 画像失败，只暂停该完整画像；同为 SHORT 的其他时段或策略仍可正常开单。

### 批次定义

同一完整画像键下，按入场时间排序。订单生命周期有重叠时属于同一批次：

```text
下一单 opened_at < 当前批次内最大 expires_at
```

边界相等，即 `opened_at == max(expires_at)`，视为新批次。算法不依赖当前2单上限，未来并发数调整后仍能正确分组。

只有批次内所有订单都已结算，批次才完成：

- 全部为 LOSS：失败批次。
- 至少一笔 WIN：非失败批次。
- 仍有 OPEN：未完成，不触发冷却。

一赢一亏不能被计为失败批次，避免重叠订单按两个独立亏损重复惩罚。

### 冷却规则

- 一个已完成的全亏批次，立即使该完整画像进入20分钟冷却。
- 冷却起点为该批次最后一笔订单的结算时间。
- 冷却期间继续保存观察画像和信号快照，只禁止该完整画像生成真实模拟订单。
- 冷却结束后恢复普通10U首单，不自动补回被拦截订单。
- 该画像在失败批次中产生或尚未消费的18U资格立即取消，恢复后的第一笔必须是10U。
- 其他完整画像不受该冷却影响。

现有按方向“三连亏、冷却20分钟”的结果序列守卫继续作为灾难兜底，用于多个画像在同一方向同时失效的情况；它不替代完整画像批次守卫。

现有“同一时段按3笔单独亏损暂停”的重复规则删除。该规则不理解订单重叠，会把同一批次的两笔亏损当作两个独立失败，同时还会误伤同一时段的其他画像。

### 状态恢复

批次和冷却状态从已保存订单重建，不新增必须维护的独立状态表：

- 服务启动时读取足够覆盖20分钟冷却和未结订单生命周期的最近订单。
- 订单结算后重新计算受影响完整画像的最后已完成批次。
- 重启前已经开始且尚未结束的冷却，重启后继续执行剩余时间。
- 缺少关键时间或画像字段的旧订单不参与批次冷却，并记录可检索告警，不能扩大为全局拦截。

## 决策顺序

修改后的开单链路固定为：

1. 使用已闭合1分钟K线生成10分钟技术特征。
2. 10分钟主策略生成 LONG、SHORT 或 WAIT。
3. 主策略没有方向时，通用 LONG/SHORT 形态生成观察候选。
4. 每日画像按完整键授权同方向候选。
5. 检查时段、滚动 edge、并发、2分钟间隔和重复信号。
6. 检查完整画像批次冷却。
7. 检查方向结果序列灾难兜底。
8. 全部通过后分配10U或一个仍有效的18U资格并原子保存订单。
9. 异步保存观察记录、画像快照和亏损详情。

任何后置守卫只能允许或否决，不能生成方向、切换方向或降低画像门槛。

## 数据兼容

- 不迁移、不重写现有 SQLite 历史订单和信号快照。
- 历史 JSON 中多余的 `mtf_30m_bias` 由兼容加载器忽略。
- 新保存的数据不再写入 `mtf_30m_bias`。
- 保留现有画像键、策略族和策略标签，确保每日画像继续使用已有样本。
- 新增的批次状态是订单派生信息，不改变订单表的结算语义。

## API 与页面

页面继续保持单行10分钟K线分析，不增加新的大卡片。调整内容：

- 删除所有“30m偏向”和30分钟周期文案。
- 守卫状态增加紧凑的“画像批次守卫”信息：完整画像键、当前批次订单数、结算结果、冷却截止时间和拦截原因。
- 订单原因明确区分 `PROFILE_BATCH_COOLDOWN` 与方向级 `RESULT_SEQUENCE_COOLDOWN`。
- API 不再输出当前 `mtf_30m_bias`，但历史订单原始快照仍可原样查询。

## 测试设计

实施使用测试驱动方式，先写失败测试，再修改实现。

### 行为保持测试

- 固定1分钟K线样本下，LONG/SHORT 通用观察候选在重构前后方向、标签和策略族完全一致。
- 10分钟主策略方向优先于通用形态。
- WAIT 不能在没有观察候选时被画像提升。
- 每日画像继续精确匹配现有完整键。

### 30分钟清理测试

- 策略运行不再聚合30分钟K线。
- `Signal`、当前API状态和页面不再包含 `mtf_30m_bias`。
- 只允许10分钟交易周期。
- 包含历史 `mtf_30m_bias` 的旧快照仍能加载。
- 当前运行代码和测试中不存在30分钟策略分支。

### 批次守卫测试

- 生命周期重叠的同画像订单归入同一批次。
- 入场时间恰好等于上一批次最大到期时间时归入新批次。
- 不同完整画像键永不合并，即使方向和时段相同。
- 未全部结算的批次不触发冷却。
- 一赢一亏不触发失败批次。
- 两笔全亏只计一个失败批次，并仅冷却对应画像20分钟。
- 同方向其他画像在该冷却期间仍可开单。
- 冷却结束后首单恢复为10U。
- 失败画像待用18U资格被取消。
- 服务重启后可以从订单恢复剩余冷却时间。
- 方向三连亏兜底仍能跨画像生效。

不把历史回测作为本次完成门槛，也不因为测试通过就自动部署。

## 验收标准

1. 运行态只存在1分钟行情输入和10分钟交易输出，不再计算或展示30分钟偏向。
2. 当前通用 LONG/SHORT 观察候选的条件、标签和画像键保持不变。
3. 完整画像的一组重叠全亏订单只形成一个失败批次。
4. 失败只暂停对应完整画像20分钟，不误伤同方向其他画像。
5. 原有方向级三连亏守卫仍作为兜底，旧的同一时段单笔计数守卫已删除。
6. 历史数据库无需迁移，服务重启后守卫状态可恢复。
7. 聚焦测试、全量测试和静态检查全部通过。
8. 本次不执行回测、不清空订单、不部署服务器；后续实施和发布分别等待确认。
