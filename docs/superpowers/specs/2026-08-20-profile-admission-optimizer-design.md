# 画像准入自动优化设计

## 1. 目标

在不启用价格结构、不修改方向预测、不增加非10分钟周期的前提下，自动寻找并验证每日常驻画像与即时画像快速通道的准入参数。

目标按硬约束和字典序执行，不使用可互相补偿的主观加权分数：

1. 样本外总胜率不低于60%；
2. LONG和SHORT胜率分别不低于55.56%；
3. 总、LONG、SHORT EV均不低于0；
4. 完整交易日日均订单位于45至55笔，排序时优先接近50笔；
5. 至少三分之二时间窗口EV为正；
6. 最大回撤和最长连亏不得劣于当前基准；
7. 多组配置同时通过时，依次比较最差窗口胜率、与50单的偏差、最大回撤、最长连亏和参数复杂度。

不存在满足全部硬约束的配置时，报告必须明确标记`release_allowed=false`，只展示最接近配置及失败项，不得自动降低门槛。

## 2. 当前证据

严格因果回放当前得到183单、98胜85负、胜率53.55%，3个完整交易日日均53.67单。LONG为65单、胜率56.92%；SHORT为118单、胜率51.69%。922个执行时间点中有729个因画像未入选而跳过，自适应状态只拦截1笔第二单，没有暂停任何已选首单。

完成生产等价缺陷修复后，方向独立的固定32组参数网格得到6组聚合达标配置。自动排名第一的候选为：

- 常驻画像允许`ACTIVE/WATCH`，LONG N12胜数上限为7，SHORT上限为9；
- LONG不增加每日画像胜率下限，SHORT每日画像胜率不低于62.5%；
- 未入选画像只允许SHORT、`ACTIVE`、N12为7至8胜且N20 EV不低于0；
- `WARMUP/PAUSED`均禁止快速准入；
- 结果为147单、89胜58负、胜率60.54%，3个完整交易日日均47.00单；
- LONG为26单、17胜，胜率65.38%，EV +2.508U；
- SHORT为121单、72胜，胜率59.50%，EV +0.684U；
- 总PnL +148U，总EV +1.007U，最大回撤94.8U，最长连亏4笔。

该候选三个时间窗口分别为54.10%、69.05%、61.36%，其中第一个窗口EV为-0.0525U，另外两个窗口为正。可用样本外仅3.21天，未形成冻结策略后的7个完整前向日，因此只能作为当前自动最优候选，不能仅凭聚合通过获得发布资格。

## 3. 共享准入模型

新增`app/profile_admission.py`，生产与回放必须调用同一纯函数，模块不得读取数据库、系统时间或订单结果。

### 3.1 通道

- `RESIDENT`：完整画像键存在于当前生效的每日画像中，且资格为`QUALIFIED`或`QUALIFICATION_WATCH`。
- `FAST`：画像未入选，但即时状态满足配置的方向、状态、N12胜数和N20 EV条件。
- `NONE`：不满足任一通道。

### 3.2 固定安全规则

- `PAUSED`阻止常驻和快速通道的首单、第二单及金额叠加；
- `WARMUP`不得进入快速通道；
- `WATCH`只允许常驻首单，禁止第二单和金额叠加；
- 快速通道只允许首单且不消费金额叠加资格；
- 快速通道不得改变候选已有方向，不得从没有观察候选的WAIT创建方向；
- 每个判断记录策略版本、通道、代码、N12/N20输入、每日资格和滚单权限。

### 3.3 参数

`ProfileAdmissionPolicy`至少包含：

```text
version
resident_allowed_states
resident_n12_max_wins
resident_long_n12_max_wins
resident_short_n12_max_wins
resident_daily_win_rate_floor
resident_long_daily_win_rate_floor
resident_short_daily_win_rate_floor
fast_enabled
fast_directions
fast_allowed_states
fast_n12_min_wins
fast_n12_max_wins
fast_n20_ev_min
fast_allow_second_order
fast_allow_progression
watch_allow_first_order
watch_allow_second_order
watch_allow_progression
```

所有整数、方向、状态、有限浮点数及上下界关系必须在构造时验证。策略生成确定性规范JSON和SHA-256哈希，生产启动参数、决策上下文、订单和回放报告引用同一哈希。

## 4. 候选选择

生产和回放先为同一闭合K线时点的全部主候选与观察候选构造`AdmissionCandidate`，再按共享规则选择：

1. 先评估每日资格和开单前即时状态；
2. 剔除`NONE`和被固定安全规则阻止的候选；
3. `RESIDENT`优先于`FAST`，避免快速通道挤掉已有稳定候选；
4. 同通道按每日画像排名、完整画像键、候选来源和候选序号确定性排序；
5. 首个候选再进入现有波段、方向健康、容量、冷却、连续亏损、金额和Webhook流程。

若排名靠前的常驻候选被画像准入阻止，选择器必须继续检查同一时点的下一常驻候选，再检查快速候选。不得像当前逻辑一样在第一个画像匹配后直接结束。

## 5. 自动搜索与防过拟合

回放只搜索小而单调的可解释网格：

```text
resident_long_n12_max_wins = 7, 8
resident_short_n12_max_wins = 8, 9
resident_long_daily_win_rate_floor = disabled, 0.60
resident_short_daily_win_rate_floor = disabled, 0.625
fast_n12_max_wins = 7, 8
```

共享常驻上限固定为12并由方向参数覆盖；快速通道固定为SHORT、`ACTIVE`、N12最少7胜、N20 EV不低于0。价格结构和其他技术指标不进入本轮搜索。网格保持32组，避免在三天样本上搜索大量自由参数。

搜索使用严格时间分段：

- 所有画像状态只读取候选开单前已结算观察；
- 每个参数评估使用相同候选集合和生产并发、方向并发、冷却及金额规则；
- 报告保留三个顺序窗口，最终发布门槛检查每个窗口；
- 参数网格和排序规则固定在代码中，不能根据当前结果动态扩展；
- 后续新增数据使用同一网格重新评估，不覆盖历史报告。

当前样本不足以进行真正独立的训练、验证、最终测试三段选参。报告必须输出`stability_proven=false`，直到候选策略冻结后累计至少7个完整前向交易日，并满足：至少5天胜率不低于55.56%、至少5天EV为正、7天合计胜率不低于60%、日均45至55单。

## 6. 运行时配置

生产不得在运行中自动搜索参数。离线回放输出通过门槛的固定策略JSON和哈希；启动脚本显式加载该策略。LONG/SHORT常驻N12上限及每日胜率下限必须独立配置。策略缺失时使用兼容基准；画像开关或候选参数非法时启动失败并明确报错，不得静默猜测参数。

本分支可携带当前最优候选作为未部署默认候选，但在`stability_proven=false`时发布状态必须为`BLOCKED`。本次不部署、不推送、不合并`main`、不创建tag、不清空订单。

## 7. 回放报告

报告新增：

- 完整搜索空间和实际评估数；
- 每组策略的规范参数、哈希、总计、方向、每日、窗口、回撤、连亏和失败门槛；
- 硬约束通过列表和字典序排名；
- 最优候选与当前基准的逐项差异；
- `aggregate_gates_passed`、`stability_proven`和`release_allowed`三个独立结论；
- 每种准入/拒绝代码的数量；
- 生产等价范围声明：报告证明画像准入层和已有回放机械规则，不宣称覆盖未进入脚本的全部线上守卫。

结构影子继续证明不改变订单，不参与自动搜索。

## 8. 测试与验收

- 纯函数矩阵覆盖RESIDENT/FAST/NONE、四种即时状态、首单/第二单、金额叠加和非法配置；
- 生产与回放对同一候选上下文输出相同准入通道、代码和排序键；
- 网格固定为32组且顺序确定；
- 排名使用原始胜负和PnL，不使用展示舍入值；
- 不达标时无可发布策略，不能降低门槛；
- 复制SQLite回放前后哈希一致，泄漏为0；
- 全量测试、Python编译、Shell和JavaScript语法检查通过；
- 任何候选只有在聚合和前向稳定性门槛都通过后才可发布。
