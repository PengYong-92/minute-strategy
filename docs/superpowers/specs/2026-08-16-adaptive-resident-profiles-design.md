# 自适应常驻画像设计

## 1. 目标与边界

将当前“最近7天每日重新入选”的画像机制改造成7天快速入选、14天稳定保留和N12/N20即时状态组成的自适应画像。程序自动决定画像的进入、保留、降级、暂停、恢复和退出，不写死人工画像名单。

本功能只处理完整观察画像键：

```text
10分钟 | strategy_family | strategy_tag | LONG/SHORT | WD/WE-UTC小时
```

本次不修改10分钟候选生成、评分、方向判断、总并发、方向并发、2分钟同方向间隔、10U/18U金额、滚单规则、Webhook和其他既有守卫。现有方向脉冲继续保持影子模式，现有24小时方向健康守卫保持原逻辑。

本设计同时整合“10分钟入场价格结构确认”。价格结构第一阶段固定为`SHADOW_ONLY`，只记录当前候选与支撑、压力、整数关口、突破、回踩和假突破的关系，不改变正式开单。自适应画像是本阶段唯一新增的正式准入变化。

## 2. 数据窗口评估

### 2.1 数据范围

线上SQLite保留全部观察记录，没有按7天删除。只读导出的BTCUSDT观察数据为：

- 8513条观察记录；
- 8511条已结算记录；
- 时间范围为2026-07-17至2026-08-16；
- 总跨度约30.06天。

因此“7天”只是当前每日画像的计算窗口，不是数据库保留期限。观察画像历史不按固定天数删除；本设计只调整必要指标和高频审计写入方式。

### 2.2 逐日前向比较

对每个北京时间07:50评估点只使用当时已经结算的独立观察样本，画像在08:00生效，再统计下一生效周期的独立观察结果。共同日期使用相同日期比较，避免不同样本期造成偏差。

| 窗口 | 共同评估天数 | 日均入选画像 | 次日留存率 | 日均新增/移除 | 前向观察数 | 前向胜率 | 前向EV |
|---|---:|---:|---:|---:|---:|---:|---:|
| 7天 | 16 | 20.44 | 80.12% | 4.53 / 4.20 | 897 | 50.72% | -0.87U |
| 14天 | 16 | 14.69 | 85.16% | 2.40 / 2.27 | 589 | 51.10% | -0.80U |

在仅有9个共同评估日的补充比较中，21天窗口日均入选9.78个、留存率91.05%、前向胜率53.43%，但覆盖率仅8.50%，且有效评估日不足，不能据此上线21天或30天窗口。30天没有完整的前向评估周期。

14天窗口相对7天窗口只将前向胜率提高0.38个百分点，却将前向观察机会减少34.34%。前向观察不是正式订单，不能直接等同订单减少比例，但足以证明“14天单窗替换7天单窗”不符合胜率和订单量双优先目标。

结论：7天继续负责快速发现当前有效画像，14天只负责稳定保留，不能成为唯一入选门槛。近期退化由完整画像键的N12/N20联合状态处理。正式实施前必须同时满足第3.4节的胜率和订单保留验收线。

## 3. 总体架构

### 3.1 稳定资格层

每日北京时间07:50同时计算最近7天和14天已结算独立观察样本，08:00生效。

两个窗口均使用现有程序阈值：

- 工作日最少20笔独立样本；
- 周末最少10笔独立样本；
- 总胜率不低于60%；
- 总EV大于等于0；
- 完整画像键隔离计算；
- 同一完整键内重叠的10分钟观察只计一次。

资格采用“快速进入、稳定退出”：

- 未启用画像只要7天窗口本次达标，立即成为`QUALIFIED`，不等待第二次日评估；
- 已启用画像只要7天或14天任一窗口达标，保持`QUALIFIED`并将联合失效次数归零；
- 两个窗口本次均不达标时标记`QUALIFICATION_WATCH`，继续保留并将联合失效次数加一；
- 两个窗口连续2次日评估均不达标后退出正式资格；
- 退出后继续记录观察，任一后续7天窗口重新达标即可恢复资格。

7天、14天统计和联合失效次数保存在每日快照的全部`candidates`中，而不只保存在`selected_profiles`中；服务重启后从最近一份每日快照恢复，不能因为重启丢失第一次联合失效记录。

首次升级到本设计且没有双窗口快照时，当前正在生效的7天画像全部作为`QUALIFIED`迁入，联合失效次数设为0，不因迁移形成空窗或等待期。

资格层不使用人工画像白名单。所有10分钟观察画像均可参与计算。

### 3.2 即时自适应状态层

每个完整画像键独立维护最近12笔和最近20笔非重叠观察结果。每次该画像有独立观察结算后立即重算，不等待07:50、整点或4小时边界。

状态规则：

| 状态 | 条件 | 正式开单行为 |
|---|---|---|
| `WARMUP` | 最近独立样本少于12笔 | 已有稳定资格时保持原行为 |
| `ACTIVE` | N12至少7胜，且N20不足20笔或N20 EV大于等于0 | 正常遵循现有开单与滚单规则 |
| `WATCH` | 已满12笔但不满足`ACTIVE`，且不同时满足`PAUSED`的两个条件 | 保留10U首单，禁止现有`DIRECTION_V2`方向第二席位和18U滚单 |
| `PAUSED` | N12最多5胜，并且N20已满20笔且EV小于0 | 阻止该画像正式开单，但继续记录观察 |

恢复使用天然迟滞：

- `PAUSED`在N12回到至少6胜，或N20 EV恢复非负后进入`WATCH`；
- `WATCH`只有在N12达到至少7胜，且N20不足20笔或N20 EV恢复非负后进入`ACTIVE`；
- 不按一笔输赢直接从`PAUSED`跳到`ACTIVE`。

N12使用离散胜场而不是近似百分比，避免边界浮点歧义：7/12为58.33%，高于10U赢8U、输10U对应的55.56%盈亏平衡胜率；6/12为50%，只能作为观察状态。N20不足时不得仅凭N12最多5胜直接停掉全部首单，避免小样本把订单量一次性压低。

### 3.3 准入顺序

保持现有候选选择和既有守卫顺序，只在每日画像资格命中后增加完整画像状态检查：

1. 生成原有10分钟候选和观察候选；
2. 检查7天快速入选和14天稳定保留资格层；
3. 附加完整画像即时状态；
4. `PAUSED`返回`ADAPTIVE_PROFILE_PAUSED`；
5. `WATCH`候选处于现有`DIRECTION_V2`方向第二席位时，返回`ADAPTIVE_PROFILE_SECOND_BLOCKED`；
6. `WATCH`首单继续进入既有机械准入，但金额固定为10U且不消费18U资格；
7. `ACTIVE/WARMUP`进入既有准入和守卫；
8. 无论是否正式开单，观察候选继续记录和结算。

完整画像状态只会收紧已经取得稳定资格的画像，不会启用未取得资格的画像、改变方向或把WAIT直接提升为订单。

### 3.4 胜率和订单量双验收线

实现后必须以当前7天生产逻辑为同区间因果基准，逐笔比较完整画像入选、候选、正式订单和金额资格。方案只有同时满足以下条件才具备发布资格：

1. 样本外总胜率不低于60%，LONG和SHORT分别不低于55.56%；
2. 总正式订单数至少保留基准的80%；
3. LONG和SHORT各自订单数至少保留各自基准的70%，不能通过停掉一个方向制造总胜率；
4. 10U首单数至少保留基准的85%，不能主要依靠关闭第二席位制造表面胜率；
5. 总EV、LONG EV和SHORT EV均大于等于0；
6. 最大回撤和最长连亏均不劣于基准；
7. 至少三分之二样本外滚动窗口EV为正；
8. 多组参数同时达标时，先按样本外胜率排序，再按订单保留数排序，最后比较最大回撤。

任一硬条件未满足时不得通过降低订单保留线或合并多空统计强行发布。价格结构影子数据不参与本轮正式准入结果。

## 4. 入场价格结构影子层

### 4.1 目标和不可偏离边界

价格结构层回答“当前候选的入场位置是否支持该方向”，不预测4小时或日线趋势，也不自行生成方向。它与画像机制各自回答不同问题：

- 7天快速入选与14天稳定保留层：这个完整画像是否具备启用资格；
- N12/N20即时状态层：这个画像近期是否退化；
- 入场价格结构影子层：这一笔候选在当前价格位置是否得到支撑、压力、突破或回踩确认。

第一阶段必须满足以下不变量：

1. 只使用当前时点已经闭合的1分钟K线；
2. 不增加30分钟、4小时、日线或外部趋势投票；
3. 不把结构状态加入完整画像键，避免拆散画像样本；
4. 不把结构结果计入7天/14天资格、N12/N20状态、动态评分或阈值；
5. 不修改`open_allowed`、候选方向、订单金额、方向席位、冷却、滚单或Webhook；
6. 不恢复历史上长期为负的120分钟假突破策略，结构层不能在没有现有候选时创建反向订单；
7. 影子开启前后的订单ID、方向、入场时间和金额必须完全一致。

### 4.2 组件和数据流

实现拆分为三个独立组件：

- `StructureDetector`：只根据已闭合1分钟K线识别确认摆动点、重复触及价格区和整数关口；
- `StructureStateMachine`：只维护接近、拒绝、突破待确认、突破确认、回踩、假突破和失效状态；
- `EntryStructureGate`：只把结构状态与候选方向、候选来源映射为`CONFIRMED/CONFLICT/PENDING/NEUTRAL`。第一阶段该结果仅为影子判断。

固定数据流为：

```text
已闭合1分钟K线
 -> 原有10分钟信号和观察候选
 -> StructureDetector
 -> StructureStateMachine
 -> EntryStructureGate(SHADOW_ONLY)
 -> 附加同一时点结构快照
 -> 自适应画像资格和即时状态
 -> 原有容量、冷却、风险守卫、金额资格与原子开单
```

三个结构组件不得读取订单结果、画像历史胜率、每日画像未来状态、滚单资格或未闭合K线。`MonitorState`只负责编排、持久化和展示。

### 4.3 因果结构识别V1

V1使用版本`ENTRY_STRUCTURE_SHADOW_V1`，固定采用下列因果口径收集线上样本：

- 历史窗口：最近240根已经闭合的1分钟K线；
- 波动尺度：以当前最后一根闭合K线计算的14周期1分钟ATR；
- 摆动点：左右各3根闭合K线，只有右侧第3根闭合后才确认中间摆动点；
- 低点只参与支撑聚类，高点只参与压力聚类；同类摆动价格的最大值与最小值差不超过0.25 ATR时属于同一区，区间边界就是该组摆动价格的最小值和最大值；
- 有效价格区至少包含2个已确认同类摆动点，两个摆动点至少间隔5根1分钟K线；普通K线高低区间与价格区相交只计为触及证据，不能替代已确认摆动点；
- 接近距离：结构边界0.35 ATR以内；
- 拒绝确认：K线高低区间与价格区相交后，支撑要求收盘高于上边界0.05 ATR，压力要求收盘低于下边界0.05 ATR；
- 突破缓冲：向上突破压力要求收盘高于上边界0.10 ATR，向下突破支撑要求收盘低于下边界0.10 ATR；
- 突破确认：连续2根闭合1分钟K线保持在结构外；
- 回踩观察：突破确认后的5根闭合1分钟K线；向上突破回踩与原区相交后收盘重新高于上边界0.05 ATR为守住，向下突破镜像处理；
- 假突破：向上突破待确认或确认后5根内收盘重新回到上边界以内，向下突破镜像处理；
- 结构失效：支撑连续3根收盘低于下边界0.35 ATR，或压力连续3根收盘高于上边界0.35 ATR。

同类型存在多个有效价格区时，按当前收盘价到区间最近边界的ATR距离分别选择最近支撑和最近压力；距离相同时依次按摆动点数量和最近确认时间排序。当前价格位于价格区内部时距离为0。状态机只追踪这两个最近结构及最近5根突破/回踩状态，使用同一240根闭合K线可在重启后确定性重建，不依赖订单或结算结果。

历史不足20根、ATR不可计算或ATR不大于0时输出`INSUFFICIENT_DATA/NEUTRAL`，不得阻断原流程。

BTC整数候选步长为100、500、1000，ETH为10、50、100。整数关口只有满足下列任一条件才成为有效结构来源：

1. 与有效摆动价格区距离不超过0.25 ATR，来源标记为`MERGED`；
2. 在240根窗口内按上述拒绝定义出现至少2次间隔5根以上的独立拒绝反应。

单纯接近整数价格不能获得`CONFIRMED`，也不能直接触发反向判断。所有距离同时计算绝对价格、基点和ATR倍数，状态判断只使用ATR倍数。

V1参数是影子样本的固定版本，不代表最优值。参数变更必须产生新版本，旧观察不得用新参数回算覆盖。

### 4.4 结构状态与方向映射

状态机至少输出：

| 状态 | 含义 |
|---|---|
| `INSUFFICIENT_DATA` | 闭合K线或ATR不足，结构层保持中性 |
| `NO_NEARBY_LEVEL` | 0.35 ATR内没有有效结构 |
| `APPROACHING_SUPPORT` | 接近支撑但尚未出现拒跌 |
| `APPROACHING_RESISTANCE` | 接近压力但尚未出现受阻 |
| `SUPPORT_REJECTED` | 触及支撑后重新收回支撑上方 |
| `RESISTANCE_REJECTED` | 触及压力后重新收回压力下方 |
| `BREAKOUT_PENDING` | 收盘已越过结构，但确认根数不足 |
| `BREAKOUT_CONFIRMED` | 满足缓冲并连续2根收盘站在结构外 |
| `RETEST_PENDING` | 确认突破后返回原结构附近，尚未证明守住 |
| `RETEST_HELD` | 回踩后重新收在突破方向一侧 |
| `FALSE_BREAKOUT` | 突破待确认或已确认后，在回踩窗口内重新收回结构内或反侧 |
| `LEVEL_INVALIDATED` | 结构已按失效规则持续穿越 |

方向映射固定为：

| 当前结构 | LONG影子判断 | SHORT影子判断 |
|---|---|---|
| 接近未突破压力 | `CONFLICT` | `NEUTRAL` |
| 压力拒绝 | `CONFLICT` | `CONFIRMED` |
| 向上突破待确认 | `PENDING` | `CONFLICT` |
| 向上突破确认或回踩守住 | `CONFIRMED` | `CONFLICT` |
| 接近未跌破支撑 | `NEUTRAL` | `CONFLICT` |
| 支撑拒跌 | `CONFIRMED` | `CONFLICT` |
| 向下突破待确认 | `CONFLICT` | `PENDING` |
| 向下突破确认或回踩守住 | `CONFLICT` | `CONFIRMED` |
| 假向上突破 | `CONFLICT` | `CONFIRMED` |
| 假向下突破 | `CONFIRMED` | `CONFLICT` |
| 数据不足、无附近结构或结构失效 | `NEUTRAL` | `NEUTRAL` |

候选来源必须单独记录：

- `NATIVE_ACTIONABLE`：原生实时LONG/SHORT且已达到自身动态阈值；
- `PROFILE_PROMOTED_WAIT`：原始实时信号未成立，但被每日画像提升；
- `RESEARCH_OBSERVATION`：仅观察候选。

同一个结构快照可以分别映射LONG和SHORT，但不能因此生成原本不存在的候选。

`candidate_origin`必须在每日画像对信号进行提升前确定：原始方向已是LONG/SHORT且原始绝对评分达到动态阈值时为`NATIVE_ACTIONABLE`；原始信号未达到该条件、随后因每日画像成为正式候选时为`PROFILE_PROMOTED_WAIT`；始终只观察时为`RESEARCH_OBSERVATION`。

当最近支撑和最近压力对同一候选产生不同判断时，最终`entry_structure_bias`按胜率优先的保守顺序选择：`CONFLICT > PENDING > CONFIRMED > NEUTRAL`。`active_level_*`保存产生最终判断的结构；同一优先级有多个结构时依次选择ATR距离更近、触及数更多、确认时间更新的结构。支撑和压力各自状态仍保留在最近结构摘要中，不能因为最终判断只保存一侧而丢失另一侧的距离和边界。

### 4.5 记录、展示和统计

结构快照必须在候选开单判断前生成，并原样附加到信号、观察样本、实际订单入口快照和订单API。不得在订单结算后根据后续K线重算。必要字段为：

```text
entry_structure_version
entry_structure_mode
entry_structure_evaluated_at
entry_structure_state
entry_structure_bias
entry_structure_reason_code
candidate_origin
active_level_source
active_level_lower/upper
active_level_touch_count
active_level_confirmed_at
nearest_support_lower/upper
nearest_resistance_lower/upper
support_distance_price/bps/atr
resistance_distance_price/bps/atr
breakout_direction
breakout_closed_bars
breakout_buffer_atr
retest_status
round_level_price/step
```

只保存当前候选的最近有效支撑、最近有效压力和决定性状态，不在每条信号中重复保存240根K线、全部历史价区或完整结构状态表。完整运行参数由6.5节的`runtime_config_hash`去重引用，纳入同一3GiB上限。

页面“最新K线分析”只增加一组紧凑结构标签；订单列表增加“价格结构”列；观察画像统计增加结构状态、影子判断和候选来源筛选。不得新增第二行重复分析卡。

观察统计必须按以下维度输出样本数、胜率、PnL和EV：

- `CONFIRMED/CONFLICT/PENDING/NEUTRAL`；
- LONG/SHORT；
- `NATIVE_ACTIONABLE/PROFILE_PROMOTED_WAIT/RESEARCH_OBSERVATION`；
- 摆动点、整数关口和`MERGED`来源；
- 支撑拒绝、压力拒绝、突破确认、回踩守住、假突破和无附近结构；
- 完整画像键及其`ACTIVE/WATCH/PAUSED/WARMUP`状态。

### 4.6 后续升级条件

影子结构不得因少量线上样本自动升级为真实门禁。只有完成因果回放并同时满足以下条件，才允许另行提出真实拦截设计：

1. 影子模式与未开启结构层的基准订单完全一致；
2. 样本外允许组总胜率不低于60%，LONG和SHORT分别不低于55.56%，两方向EV均大于0；
3. `PROFILE_PROMOTED_WAIT`的`CONFIRMED`组胜率至少比其余结构组高3个百分点，且不是单一时段贡献；
4. 未来真实门禁方案总订单至少保留基准80%，LONG和SHORT分别至少保留各自基准70%；
5. 最大回撤和最长连亏不劣于基准；
6. 至少三分之二样本外滚动窗口EV为正；
7. BTC和ETH分别满足条件，不互相掩盖；
8. 任何真实拦截都必须单独设计、单独确认，不得在本分支影子阶段暗中启用。

## 5. 时间段展示

画像键中的`WD/WE-xx`使用UTC日期类型和UTC小时。页面和API必须同时输出：

- 原始`threshold_segment`，例如`WD-18`；
- UTC小时范围，例如`18:00-18:59 UTC`；
- 北京时间范围，例如`次日02:00-02:59`；
- 北京时间是否跨日；
- 方向、策略族和策略标签；
- 7天和14天各自样本、胜率、PnL和EV；
- N12/N20样本、胜率和EV；
- 资格状态、即时状态和变化原因；
- 最近状态更新时间。

北京时间只作为展示字段，不能替换画像键或改变既有WD/WE归属。例如`WD-22`仍是UTC工作日22点画像，页面显示为北京时间次日06:00-06:59。

页面按完整画像列出所有已评估时段，并支持方向、WD/WE、资格状态和即时状态筛选。用户后续可以根据该表决定是否需要增加人工时段限制，但本次不增加人工时间白名单。

## 6. 数据加载、统计与容量治理

### 6.1 运行态加载

- 启动和币种切换时加载最近15天观察记录，覆盖14天资格窗口和边界结算。
- 即时状态只需要每个完整键最近20笔独立结果，可由最近15天记录恢复。
- 每日资格快照继续写入`daily_profile_selections`，保存7天/14天统计和联合失效次数；即时状态由最近15天观察在内存中计算，重启时重建，不把每笔结算重复写回每日快照。
- 观察和模拟订单载荷新增完整画像状态的必要字段及`runtime_config_hash`；高频信号审计使用6.5节的精简格式，不重复整份状态和配置。旧载荷字段缺失时按`WARMUP`兼容。

如果某个画像在15天内仍不足12笔即时恢复数据，N12/N20按实际样本计算并保持`WARMUP`，不会读取未来数据或用其他画像补样本。

### 6.2 观察统计读取

当前`OBSERVATION_SUMMARY_LIMIT=5000`只覆盖约17.6天，不能继续作为主要画像统计口径。修改后：

- “观察画像统计”默认展示最近14天，同时显示同一画像的7天快速窗口结果；
- API和页面支持`7天 / 14天 / 30天 / 全部数据`；
- 每个窗口按`opened_at`时间查询，不按最近固定条数截断；
- 观察明细使用SQLite的`COUNT + WHERE + ORDER BY + LIMIT/OFFSET`真实分页，不先加载最近5000条再内存分页；
- 自适应画像运行态快照不依赖通用统计接口；
- 方向脉冲仅需要N12/N16，启动恢复继续最多读取最近5000条，不影响其正确性。

“全部”读取数据库中现存的全部观察画像，不再受5000条限制。

### 6.3 线上容量依据

2026-08-17只读统计显示：

| 数据 | 行数 | SQLite占用 |
|---|---:|---:|
| `signal_audit` | 695672 | 约1.570GB |
| `observation_signals` | 8521 | 约12.4MB |
| `order_entry_snapshots` | 547 | 约9.8MB |
| `orders` | 547 | 约1.6MB |
| 整个数据库 | - | 约1.615GB |

`signal_audit`占数据库约97%，观察画像不是当前体积问题。最近14天信号审计为97892行、载荷约219MB；最近30天为224899行、载荷约398MB。SQLite表页和索引会使实际占用高于载荷大小。

### 6.4 必要指标口径

数据库容量控制以“只记录可用于画像筛选、订单归因和状态复盘的数据”为主，不以固定天数清理历史为主。

`observation_signals`是画像筛选的主要数据。每条观察除身份、开平时间和结果外，需要保存：

- 完整画像键、方向、UTC时段、策略族和策略标签；
- 入场点位、到期点位、胜负、PnL；
- `score`、`threshold`、`calculated_threshold`和`edge`；
- 量比、量能阈值、10分钟涨跌幅、价格位置和收盘强度；
- MACD柱、MACD柱变化、RSI、BOLL位置和BOLL宽度；
- 10分钟偏向、行情状态、Fear & Greed值和变化状态；
- 每日画像版本、7天/14天统计、资格状态和联合失效次数；
- N12/N20即时状态、样本、胜率、EV和状态更新时间；
- 订单席位、质量评分、最终决策码及关键守卫状态；
- 4.5节定义的价格结构版本、模式、状态、影子判断、候选来源、最近价区和ATR距离。

上述字段足以重新计算画像胜率、EV、时段表现、指标分布、状态迁移和决策影响，不在观察记录中重复保存整份全局配置或其他方向的运行态。

`orders`和`order_entry_snapshots`继续保存真实模拟订单的完整入场证据，因为订单数量远低于每分钟信号。金额链路、最终守卫结论、入场K线和结算结果不精简。

### 6.5 高频信号审计精简

当前`signal_audit`每次闭合1分钟K线都保存完整`signal.to_dict()`，并重复保存全部滚动优势、结算序列、波段批次、画像退化、画像健康、方向脉冲和画像守卫配置。这些重复快照是数据库膨胀的主要原因。

修改后使用`SIGNAL_AUDIT_V2`：

1. 决策、方向、周期、时段、行情状态、分数、阈值和原因继续使用独立列；
2. JSON载荷只保存画像身份、每日画像版本、订单席位、关键指标、质量评分摘要、自适应画像状态、价格结构影子摘要和各守卫的`status/code`及决定性数值；
3. 不再写入`quality_score_inputs`，因为其输入已由独立指标字段覆盖；
4. 不再逐行重复保存全部守卫配置、全部方向脉冲快照和完整每日画像候选列表；
5. 运行参数生成`runtime_config_hash`，完整配置只在新表`runtime_config_snapshots`中按哈希保存一次；审计、观察和订单只引用该哈希；
6. 正式开单、正式候选被阻止、自适应画像状态变化、守卫状态变化必须立即保存独立审计行；
7. 连续且状态完全相同的普通`WAIT/BELOW_THRESHOLD`按10分钟桶聚合，保存`first_at`、`last_at`、`occurrences`、最小/最大分数和最后一次指标快照，不再每分钟重复整行；
8. 观察画像仍由`observation_signals`逐笔记录，不能因为审计聚合而漏掉观察结果。

旧`signal_audit`保持可读，不重写、不迁移、不删除。统计接口同时兼容旧版单行记录和V2聚合记录，命中数量使用`occurrences`还原。

### 6.6 3GB文件峰值

单个`monitor.sqlite3`文件上限设为3GiB：

```text
3 * 1024 * 1024 * 1024 = 3221225472 bytes
```

容量状态：

- `NORMAL`：小于2.5GiB，按V2正常记录；
- `WARNING`：达到2.5GiB，页面和`/api/state`持续告警；
- `COMPACT_ONLY`：达到2.75GiB，停止普通WAIT心跳聚合，只保存订单、观察、自适应状态变化和决定性阻止事件；
- `HARD_LIMIT`：达到3GiB，禁止继续分配SQLite页面；若核心数据也无法写入，沿用现有存储失败保护，暂停新开单，绝不创建无法持久化的订单。

实现时根据实际`page_size`设置`PRAGMA max_page_count`，使物理上限严格等于3GiB。为核心表预留至少256MiB，不把3GiB全部分配给`signal_audit`。可选审计的写入预算上限为2.75GiB减去当前核心表占用；达到预算后只停可选审计，正常情况下不影响行情消费、画像结算、模拟订单或Webhook。

本次不执行固定TTL清理、不删除历史观察和订单、不压缩或重写线上现有1.615GB数据库。容量控制来自V2字段精简、重复配置去重、普通WAIT聚合和可选审计预算。达到`WARNING`后是否归档历史数据作为后续独立运维决策，不包含在本次功能范围内。

## 7. 异常处理

- 即时状态计算异常时记录`last_error`并沿用该画像上一份有效状态，不得阻断其他画像和行情消费。
- 每日资格计算异常时沿用当前有效资格快照，行为与现有`FALLBACK`一致。
- 存储失败继续遵循现有存储错误路径，不先开单后补审计。
- 状态重算必须只使用`settled_at <= current_time`的观察，回放、延迟消息和重启均不得读取未来结果。
- 结构计算失败时写入`entry_structure_state=ERROR`和短错误码，并按`NEUTRAL`影子展示；不得阻断候选、画像或订单。
