# 10分钟市场序列策略设计

## 目标

用原始1分钟K线构建独立于旧量价评分、固定时段白名单和订单胜负方向的10分钟市场序列策略。策略每天北京时间07:50使用此前7天数据评估，08:00生效，输出 `LONG`、`SHORT` 或 `WAIT`。

## 原则

- 只使用决策时已经闭合的K线，训练标签必须在评估截止时间前完成。
- 市场标签由10分钟后的价格相对入场价格确定，不使用原订单方向推导。
- 训练样本按10分钟步长取样，防止把重叠的10分钟收益当作独立证据。
- 开单候选按2分钟步长产生，继续遵守最多5个未结订单限制。
- 不加入4小时或日线趋势，不依赖 Fear & Greed 决定方向。
- 旧策略继续生成观察画像，但启用序列策略时不参与主开单决策，也不作为序列策略无信号时的回退。

## 状态模型

每个候选时点使用以下当时可见信息：

- 最近滚动10分钟价格方向：`UP` 或 `DOWN`。
- 同方向连续长度：`1`、`2`、`3-4`、`5+`。
- 最近10分钟量能相对过去24个非重叠10分钟窗口中位数：`LOW`、`NORMAL`、`HIGH`。
- 14周期1分钟RSI：`LOW`、`NORMAL`、`HIGH`。

模型支持三个键空间：

- `move_run`
- `move_run_volume`
- `move_run_volume_rsi`

每日快照对每个状态统计上涨、下跌、胜率、EV和95% Wilson下界。状态必须达到最小独立样本数、最低观察胜率和正EV才可启用。预测方向取样本多数方向；平局不启用。

## 运行流程

1. 启动时加载历史K线并从SQLite恢复观察画像。
2. 首次实时更新根据当前时间对应的07:50截止点构建当日序列快照。
3. 08:00后，每个满足2分钟对齐的闭合1分钟K线计算当前状态。
4. 当前状态在快照中启用时生成序列信号，否则返回 `WAIT`。
5. 序列信号进入现有并发、最小间隔、滚动优势和金额叠加流程。
6. 页面显示快照版本、状态键、训练样本、方向、胜率、EV和当前是否入选。

## 回放与参数选择

回放必须按日扩展窗口运行：当天07:50只使用此前7天且已经结算的标签，当天08:00后执行。参数矩阵包含键空间、最小样本数和最低胜率。先在前80%日期选取参数平台，再把最后20%日期作为一次性留出集；报告分别给出单订单、最多2单和最多5单的订单数、方向、胜率、收益、EV、最大回撤和逐日结果。

参数选择优先级为：留出集收益为正、留出集胜率高于55.56%、相邻参数同向盈利、最大回撤较小、订单数量不过度集中在单日。不得直接采用同一段数据中的单点最高收益参数。

## 持久化与清理

序列快照由历史K线确定，运行时保存在内存并通过状态API展示，不新增必须迁移的数据库表。发布前备份数据库，仅清空以下订单运行态数据：

- `orders`
- `order_entry_snapshots`
- `stake_progression_credits`
- `stake_progression_runtime`

保留 `observation_signals`、`daily_profile_selections` 和历史K线缓存，确保启动后可立即预热和继续研究。

## 失败处理

- 历史K线不足、每日评估失败、无合格状态或当前状态未入选时统一 `WAIT`。
- 不回退旧策略开单。
- 存储失败继续沿用现有 `STORAGE_ERROR` 停单逻辑。
- 部署后必须验证预热状态、序列快照状态、订单列表为空和服务健康。
