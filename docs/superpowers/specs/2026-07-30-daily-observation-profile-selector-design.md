# 每日观察画像策略选择器设计

## 目标

观察画像不是单条信号的临时放行器，而是主程序的策略选拔器。系统全天记录所有候选画像的影子结果，每天北京时间 07:50 使用此前 7 天已结算的独立样本完成一次评估，生成从当天 08:00 到次日 08:00 固定生效的画像集合。主程序只执行当前启用画像对应的信号，其他画像继续观察但不开单。

## 画像身份

画像的最小选择单位为：

```text
timeframe_minutes + strategy_family + strategy_tag + direction + threshold_segment
```

不能只按 `WD-01`、`WD-02` 选择，因为同一时段内可能同时存在 LONG、SHORT 和不同量价结构。选择与执行必须使用完整画像身份，防止把一个画像的历史优势错误应用到另一个信号。

## 每日评估周期

- 时区固定为 `Asia/Shanghai`，不依赖服务器本地时区。
- 每天 07:50 后出现的第一根已完成 K 线触发当日评估。
- 统计截止时间固定为当天 07:50，窗口为 `[截止时间 - 7天, 截止时间)`。
- 仅使用截止时间前已结算的 `WIN`/`LOSS` 观察样本，未结算样本不参与。
- 同一画像中开仓时间早于上一样本到期时间的记录视为重叠，只保留第一条，避免重复 K 线夸大样本量。
- 评估结果从当天 08:00 生效，到次日 08:00 失效；盘中不重新排名或切换。
- 服务在 08:00 后启动且当天尚无评估记录时，立即补算当日快照，仍使用当天 07:50 截止的数据。

07:50 评估不能使用尚未产生的 08:00 数据，因此统计窗口以 07:50 为真实截止点。这修正了口头方案中“07:50 评估但统计到 08:00”的时间矛盾。

## 选择规则

初始参数全部可通过启动参数配置：

- 回看周期：7 天。
- 最小独立样本：20。当前服务器最近7天精确画像通常为23至28条，30会导致首日没有可启用画像。
- 入选胜率：不低于 60%。
- 入选 EV：不低于 0U。
- 启用数量：不设固定上限，避免高胜率合格画像因排名被挤出。
- 最大启用画像：4 个；不足 4 个时不强行补足。
- 排序：先按胜率降序，再按 EV、样本量降序，最后按画像 key 排序，保证结果可重放。

退出采用滞后条件，避免画像一天入选、第二天立即退出：

- 已启用画像胜率低于 60% 或 EV 不大于 0 时，于当次日评估退出。
- 连续两个每日评估周期退化后退出。
- 样本因窗口滚动降到最小样本以下时同样记一次退化，不立即退出。
- 新画像只有达到入选阈值才能进入，不继承旧画像的退化宽限。

画像统计和页面现有的 `PROMOTE_WATCH` 展示标签分离。`PROMOTE_WATCH` 只表示值得观察，不代表已被主程序启用。

## 执行流程

每次 K 线更新仍先生成当前主信号和观察候选。系统根据候选信号的完整画像身份查询当前生效快照：

1. 画像未启用：保留观察记录，主程序不开这条画像订单。
2. 画像已启用：把观察方向转换为本次可执行方向，并附加选择快照的样本量、胜率、EV 和版本号。
3. 动态画像只替代静态时段/动态阈值/技术指标的开单资格，不绕过通用风险控制。
4. 最大持仓、冷却、重复信号、同日同画像连续亏损、滚动守卫、画像守卫、金额和滚单规则继续执行。
5. Webhook 与订单快照记录实际采用的画像 key 和每日选择版本，便于后续区分不同策略版本。

技术指标不做全局删除。对于 `generic_*_observe` 这类画像，指标可以不作为硬开单门槛，但原始方向、量价状态、影线结构和完整画像身份仍必须匹配。其他依赖指标的策略继续使用原有指标定义。

## 持久化

新增每日选择快照存储，至少包含：

- symbol、评估时间、统计开始/截止时间、生效开始/结束时间。
- 配置参数和选择状态：`READY`、`FALLBACK`、`FAILED`。
- 所有候选画像的样本量、胜率、EV、盈亏、入选/淘汰原因。
- 最终启用画像列表及每个画像的连续退化次数。
- 唯一键 `symbol + effective_from`，重复触发时幂等更新。

服务启动和切换币种时加载当前生效快照。数据库写入失败或评估异常时沿用上一份有效快照并标记 `FALLBACK`；不存在历史快照时保持当前静态基准，不允许因为异常生成空策略集合。

## 页面与接口

`/api/state` 增加每日画像选择状态：

- 上次评估时间、统计窗口、当前版本、生效区间、下次评估时间。
- 当前启用画像及各自样本量、胜率、EV。
- 状态与失败/沿用原因。

页面将“观察画像”与“当前启用画像”分开显示。观察画像表增加“已启用/候选/退化/未达标”状态和原因；页面不再把 `PROMOTE_WATCH` 表述为自动放行。

## 与旧逻辑的关系

现有 `_observation_profile_promoted_signal` 的单信号放行语义停止使用，避免每日选择器与临时放行产生两套决策。旧启动参数保留一版兼容解析并映射到新选择器参数，运行状态明确展示使用的是每日选择模式。

## 验证

- 单元测试覆盖完整画像分组、重叠样本去重、7 天边界、排名和滞后退出。
- 状态测试覆盖 07:50 前不评估、07:50 后只评估一次、08:00 生效、重启补算和失败沿用。
- 订单测试确认启用画像可以执行，未启用画像只观察，并且所有通用风险控制仍有效。
- 存储测试覆盖快照幂等、当前快照恢复和失败状态。
- 页面测试覆盖启用画像状态与中文说明。
- 发布时记录明确的策略版本和生效时间，不清空已有观察样本或历史订单。首次每日选择允许使用发布前最近 7 天的已结算观察样本。
- 发布后按策略版本持续统计实际订单数、胜率、EV、盈亏、最大回撤和 LONG/SHORT 分项，作为后续参数调整依据。

## 验收标准

- 同一交易日内启用画像集合保持不变。
- 每日评估与实时执行使用同一画像身份和时间边界定义。
- 订单可追溯到唯一每日选择版本和完整画像 key。
- 评估失败不会清空策略，也不会绕过风险控制。
- 动态选择器直接以开单模式发布；发布后的真实订单必须能按每日选择版本独立复盘，不能与发布前样本混合评价。
