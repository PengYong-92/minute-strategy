# 可配置开单阈值与画像执行设计

## 背景

2026-08-06 23:56:23 发布的 `e824cf5` 在生产运行约10小时后仍没有订单。生产审计显示本次启动后的3405次判断全部为 `BELOW_THRESHOLD`；最高评分46.5、最低动态阈值77.8，没有信号进入每日画像、1分钟波段或批次守卫。

根因是 `891a844` 将每日画像从“主策略选择器”改为“已过线信号验证器”。基础策略必须先独立通过动态阈值和静态时段 edge，画像才有机会参与；而当前评分分布无法达到该前置门槛。

## 目标

1. 通过启动参数手动控制实际开单阈值，生产首次设置为0。
2. 每日画像可以把当前主信号的观察方向转换成候选方向，但只能精确匹配已启用画像。
3. 画像选出方向后必须再经过1分钟波段、批次、并发、间隔和其他风险守卫。
4. 每笔订单保存并展示实际开单阈值、原始动态阈值和评分。
5. 后续调整阈值只修改服务器启动参数并重启，不重新发布代码。

## 非目标

- 不自动按时间或样本上调阈值。
- 不调整65%画像入选和退出规则。
- 不放行未入选画像。
- 不执行研究观察候选。
- 不调整1分钟波段算法、两单批次、滚单金额或并发上限。

## 启动参数

新增统一配置：

```text
TRADE_SCORE_THRESHOLD=auto
--trade-score-threshold auto
```

语义：

- `auto` 或空值：保留程序计算的动态阈值，不允许画像提升未过线信号。
- `0`：已入选画像不受评分限制，评分为0也可成为候选方向。
- `0 < N <= 95`：已入选画像要求 `abs(score) >= N`。
- 负数、非数字或大于95的值拒绝启动。

代码默认使用 `auto`，生产 systemd drop-in 显式设置 `TRADE_SCORE_THRESHOLD=0`。

## 决策顺序

每轮仅处理当前10分钟主信号，不执行研究观察候选：

```text
10分钟主信号与观察方向
  -> 今日画像按 timeframe/family/tag/direction/segment 精确匹配
  -> 应用实际开单阈值
  -> 形成 LONG/SHORT 或保持 WAIT
  -> 附加并执行1分钟波段方向守卫
  -> 每日画像未入选拦截
  -> 并发、2分钟间隔和重复信号
  -> 波段批次、恢复、旧兼容守卫
  -> 开单与持久化
```

关键约束：

- 画像匹配方向使用 `observe_direction`；没有 `LONG/SHORT` 观察方向时不能生成方向。
- 完整画像 key 不匹配时不能开单。
- 数值阈值未达到时保持 `WAIT`，但状态中保留画像匹配和阈值信息。
- 阈值达到后才把方向设为画像方向。
- 1分钟波段在画像确定方向后执行，确保画像不能绕过方向守卫。
- `TURN_UP`、`TURN_DOWN`、`RANGE_MID`、`UNKNOWN` 仍不允许开单。

## 数据模型

`Signal` 和 `SimulatedOrder` 新增：

```text
calculated_threshold: float
```

字段语义：

- `score`：开单时实际评分。
- `threshold`：实际开单阈值；生产首次为0。
- `calculated_threshold`：原策略计算出的动态阈值，例如79.1。

旧订单缺少 `calculated_threshold` 时，API和页面回退使用 `threshold`，无需SQLite结构迁移。

## 页面

模拟订单表在“时段胜率/EV”和“金额”之间新增“开单阈值”列：

```text
0.0
评分 0.0 · 原始 79.1
```

空表 `colspan` 同步从16调整为17。订单筛选和分页行为不变。

## 状态和审计

`/api/state` 新增 `trade_score_threshold`：

```json
{
  "mode": "OVERRIDE",
  "value": 0.0
}
```

自动模式返回 `{"mode":"AUTO","value":null}`。订单入口快照同时保存该配置，确保后续复盘能证明当时阈值状态。

## 验证

单元测试必须证明：

1. `auto` 不提升 `WAIT`。
2. 阈值0允许精确匹配的当前主画像形成方向。
3. 正数阈值只在评分达到后形成方向。
4. 未入选画像和研究观察候选不能开单。
5. 画像方向必须在之后经过1分钟波段；方向冲突不能开单。
6. 订单保存实际阈值、原始阈值和评分。
7. 页面新增列且空表列数正确。
8. 参数解析拒绝非法值。

发布验证必须确认服务、HTTPS、预热和SQLite正常，API显示阈值覆盖为0，并观察审计决策不再100%停留在 `BELOW_THRESHOLD`。本次不清空观察样本；订单当前为0，因此无需清理订单。
